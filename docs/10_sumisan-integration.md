# 墨さんと HIRAKU — どこを混ぜるか

2026-08-22 / 建石 × 横森

## 1. 二つは、同じ一周の別の区間を見ている

墨さんは五工程を通しで見る道具。HIRAKU は、そのうち「直す」を深く掘る道具。

| 工程 | 墨さん | HIRAKU |
|---|---|---|
| 出会う | 8つの問診 → 🚦判定 | 探す・法規診断 |
| 確かめる | 台本・帳面 | 内見チェック・地域パック |
| 手に入れる | 「待った」を言う | （無い） |
| **直す** | 順番だけ言う | **実測・作図・敷地・改修案・概算・パース・見積書** |
| ひらく | カルテに締める | 現況調査報告書・御見積書 |

結論：**HIRAKU は墨さんの「直す」章の中身になる。** 別アプリとして並べるのではなく、
墨さんのカルテから呼ばれる一つの深い部屋にする。

## 2. 混ぜるべきところ

### (a) 帳面 ＝ 確度（いちばん大事）
墨さんの「確かめた事実（出どころ＋日付）」と、HIRAKU の確度三色
（推定＝灰／仮説＝黄／実測＝緑）は、同じ思想の別表現。ここは一本にする。

- 窓口回答・登記・実測 → **実測（緑）**
- 図面から読んだ数字・モジュール推定 → **仮説（黄）**
- 埋めただけの数字 → **推定（灰）**

HIRAKU 側はすでに、数値で打ち込んだ寸法を実測として扱っている。
墨さんの帳面に載せるとき、この三色をそのまま持っていける。

### (b) 順番の規則
墨さんの「許認可に要る → 客を呼ぶ → あとまわし」は、そのまま HIRAKU の
改修案の並べ方にした（一段目／二段目／三段目）。**ここは完全に一致させた。**
順番の言葉は墨さんの語（切り墨）を使う。

### (c) 芯
墨さんの芯墨＝「この場は何のための場か」。HIRAKU のヒアリングの一問目も芯にした。
**芯は一度だけ聞いて、両方が参照する。** 二度聞かせない。

### (d) 一枚のカルテ
墨さんの「相手にアプリを入れさせない一枚」に、HIRAKU の成果物を差し込む。

- 平面図（実測の色つき）
- 敷地の配置図（住所・方位・縮尺）
- 内見チェックの結果（要対応→気になる→問題なし）
- 改修案（三つの構え、段つき）
- 概算レンジ、または御見積書

カルテは墨さんが締める。HIRAKU は**そこに貼る紙を作る道具**として振る舞う。

## 3. 混ぜないほうがいいところ

- **買う判断**：墨さんは一度もしない。HIRAKU も改修の話しかしない。ここは分けたまま。
- **診断書**：どちらも書かない。HIRAKU は構造・耐震に踏み込まない（D17）。
- **AIの声**：墨さんは「墨丸をとんとん」の対話。HIRAKU は道具の画面。
  同じ人格にしなくていい。墨さんが番頭で、HIRAKU は作業場。

## 4. 受け渡しの形

一方向でいい。墨さんの帳面 → HIRAKU（物件の芯・用途・判定・確かめた事実）、
HIRAKU → 墨さんのカルテ（図面・敷地・チェック・案・金額）。

```
{ core, use, verdict, facts[{label, source, date}], deadline }   →  HIRAKU
{ plan, site, checklist, proposals, estimate, quote }            →  カルテ
```

HIRAKU の Project 型はすでにこの形に近い（model / site / checklist / proposals / quote）。
JSON で書き出せるので、当面はファイル渡しで足りる。

## 5. HIRAKU 側で、すでに寄せたこと

- 改修案を「安い・普通・高い」から「開けるところから／芯を太く／引いて残す」に変えた
- 手順を三段（開けるために要る／開けた日に効く／あとからでいい）で並べた
- どの案にも「今回はやらないこと」「置いている前提」「次の一手（多くて2つ）」を付けた
- ヒアリングの一問目を芯にし、どの問いにも「なぜ聞くのか」を添えた
- 見出しを明朝にし、罫線と余白で仕様書のように組んだ

## 6. まだ決まっていないこと

- 名前をどうするか（墨さんの下に入るのか、二枚看板か）
- 記録の置き場（どちらも端末の中。共有するなら本人の同意の形をそろえる必要がある）
- 伴走の線引き（墨さんの伴走に、HIRAKU の作図代行を含めるか）
